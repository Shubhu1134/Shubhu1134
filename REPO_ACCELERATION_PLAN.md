# Public Repo Acceleration Plan

Goal: maximize visible GitHub progress with public, PR-based contributions that can merge quickly.

## Repo Selection Rule
Prioritize repositories that already have one of these qualities:
- active or recently pushed
- enough content for small same-day PRs
- strong visibility on your profile
- good signal for Java, web, DevOps, or AI learning depth

## 14-Day Execution Split

### Days 4-7
- `docker-deploye-architecture`: one deployment checklist or docs PR
- `prompt-engineering`: one prompt library/examples PR
- `SQL` or `code-in-java`: one notes or cleanup PR
- one review block or one discussion answer

### Days 8-14
- `notes`: one index or learning-map PR
- `Devops-Foundations`: one starter README or workflow PR
- `ci-cd-demo`: one pipeline overview or badge PR
- `Team-Practice-Java-Projects`: one setup or contribution docs PR
- one external contribution PR

## PR Shapes That Merge Fast
- README restructuring
- setup instructions
- example folders
- starter workflows
- deployment checklists
- bugfixes with short reproduction notes
- topic indexes and learning maps

## Non-Negotiable Rules
- Every change starts with an issue
- Every issue ends with a merged PR
- Keep PR scope small and shippable
- Prefer public repos over private work when you want visible momentum
- Log weekly output in sprint issues
