# Achievement Sprint System

Use this system every week to build visible GitHub momentum fast.

## Weekly Setup
- Confirm the Monday sprint issue exists
- Pick the first three issues before writing code
- Keep every issue small enough for one focused PR
- Prefer public repo work when the goal is visible momentum
- Log merged PRs and review activity in the weekly sprint issue

## Weekly Targets
- 5 merged pull requests (own + external repos)
- 3 closed issues linked to PRs
- 2 meaningful code reviews/comments
- 1 discussion answer
- 1 VPS/DevOps improvement with docs

## Daily Cadence (60-90 min)
1. Pick one small issue.
2. Create branch and implement.
3. Open PR with checklist.
4. Merge and close issue.
5. Log outcome in weekly sprint issue.

## Weekly Repo Order
1. `Shubhu1134` for visible profile and system upkeep
2. `WebDevelopment` for fast docs and fix PRs
3. `Advance-java-code-` for structured Java examples and notes
4. `docker-deploye-architecture` for DevOps and deployment signal
5. one external public repo for collaboration proof

## Sprint Issue Operating Rule
- Treat the Monday sprint issue as the execution log for the whole week
- Add every merged PR link back into that issue
- Keep at least one `docs`, one `fix`, and one `feat`, `chore`, or `ci` change in flight each week
- If you miss one day, do not restart the plan; continue from the next highest-priority repo
- Close the week with a review issue or weekly summary before the next sprint starts

## High-Leverage Repo Types
- Active public repos where you can submit small fixes quickly
- Your own repos with clear issue/PR workflow
- DevOps repos with CI/CD, Docker, deployment scripts

## Minimum Output per Week
- One merged `feat`
- One merged `fix`
- One merged `docs`
- One merged `chore` or `ci`
- One external contribution PR

## Scorecard

| Signal | Target | Notes |
| --- | --- | --- |
| Merged PRs | 5 | Mix own repos and external contributions |
| Closed linked issues | 3 | Prefer issue -> branch -> PR -> close |
| Reviews/comments | 2 | Make them specific and useful |
| Discussion answer | 1 | Aim for one accepted or helpful answer |
| DevOps improvement | 1 | CI, deployment, Docker, VPS, or docs |

## PR Mix
- `docs`: README cleanup, topic index, setup guide, deployment checklist
- `fix`: broken link, incorrect setup step, workflow bug, failing example
- `feat`: new example, reusable template, small automation
- `chore`: repo cleanup, labels, templates, dependency housekeeping
- `ci`: workflow, check, badge, or release verification improvement

## Notes
- Achievement badges are event-driven and can take time to appear.
- Keep activity consistent; consistency wins over one large dump.
